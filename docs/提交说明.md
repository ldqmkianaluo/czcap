
### 第 2 步｜离线自检（不联网、不花钱，约 10 秒）

双击根目录的 **`自检.bat`**，或执行：

```powershell
python code\selftest.py
```

**预期输出**（最后一行）：

```
结果：全部通过
```

这一步跑的是 68 项离线断言，覆盖一致性度量、图像遮蔽、滑动窗口的覆盖完整性、问法改写、指标计算、yes/no 解析边界。它不调用任何模型，所以评审无需 API Key 也能验证代码本身是对的。

### 第 3 步｜打开网页演示

把 `.env.example` 复制成 `.env` 并填入自己的 `VLM_API_KEY`，然后双击 **`启动演示.bat`**，或：

```powershell
python code\server.py
```

浏览器打开 **http://127.0.0.1:8000**，上传 `images/01.png`，输入任意是非问句，点「开始检测」。

| 模式 | 调用次数 | 耗时 | 说明 |

### 3.2 这份快照是什么

- **48 轮提问**，覆盖 **2026-10-07 11:14 → 2026-11-01 19:45**，即从「选题」到「打包提交」的完整过程；
- 由脚本 `tools/export-ai-log.mjs` 从 DSH 会话记录直接导出，**内容未经人工删改**；
- 每条记录都带**本地时间（UTC+8）**，可以直接和 git 提交时间对照；
- 剔除了三类非用户输入的记录：客户端自动注入的运行时上下文与系统提示块、上下文压缩器插入的历史摘要、后台任务完成回执（否则这些自动消息会被计成"提问轮次"）；
- 同一场对话的多份导出只保留内容最全的一份；
- **为什么是 48 轮**：该会话导出到 11-16 共 53 轮，第 49–50 轮是收到的评审反馈原文，第 51–53 轮是三次 `/compact`（上下文压缩命令）。这 5 轮没有产生代码或文档，且那份导出里前 48 轮的工具调用结果被截断（840 条 → 420 条），所以选用内容完整的 48 轮版本，评审反馈之后的补齐过程另见 11-16 的补快照。


### 3.3 三十秒核验路径

1. 打开快照，文件开头是**「提问轮次索引」表**：`轮次 / 时间 / 提问首行 / 定位`；
2. 想知道某轮具体说了什么、AI 做了什么 → 点该行「跳转」，正文有锚点；
3. 想知道**哪一轮催生了哪个功能** → 看下面第四节的「演进链路」表，它把提问轮次、产出、git 提交三者对在了一起。

整个过程证据链是：**提问（快照第 N 轮，带时间） → 产出（文件/功能） → 提交（git commit，带时间）**，三者的时间戳能互相咬合。
