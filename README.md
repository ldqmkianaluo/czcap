# HaluLens

**面向黑盒视觉大模型的幻觉检测与区域归因**

> 不只告诉你模型答错了，还告诉你它错在哪一句、看错了图上哪一块。

---

## 这个项目解决什么问题

视觉大模型（VLM）在图像问答中会产生**看似合理却毫无图像依据的陈述**，而这类错误在表达上与正确答案无法区分——模型编造"图中有一只猫"时，语气和它说真话时完全一样。

这个问题在**无人复核的自动流程**中尤其危险：电商平台自动为商品图生成描述、系统为视障用户朗读图像内容。此时一句编造的话会直接误导使用者，且没有任何机制能拦住它。

现有的幻觉抑制方法大多是**白盒方法**（对比解码、注意力重分配等），需要访问模型的注意力图或隐层激活。但真实使用者拿到的是 API——**拿不到权重，也没法要求服务商为自己的需求改造模型**。所以白盒方法在实际场景中无法施加。

本项目放弃对模型内部的全部依赖，只用"输入—输出"这一对可观测量。

## 方法：三种黑盒测试

### 测试 A｜提问改写一致性
对同一视觉事实构造多种语义等价的问法，比较答案分布。幻觉陈述的答案分布更发散，因为模型并非基于图像作答，而是在语言先验上采样。

### 测试 B｜图像扰动一致性
对图像施加**与问题语义正交**的变换（裁剪、JPEG 压缩、缩放），观察答案是否保持。

> 关键难点：变换必须与问题语义正交。若问题是"图中汽车是什么颜色"，调整亮度会真实改变答案，此时答案变化不是幻觉信号。因此按问题类型筛选可用变换，该局限在技术文档中已披露。

### 测试 C｜遮蔽敏感性归因（核心机制）
把图像划分为网格，逐格遮蔽后重新提问，观察答案是否翻转：

- **存在使答案翻转的格子** → 该陈述依赖图像证据，得到依赖区域；再核验该区域内容是否支持该陈述。支持则判为正确，不支持则判为**视觉误读型幻觉**并高亮该区域。
- **不存在任何使答案翻转的格子**（答案恒定） → 判为**无视觉依据型幻觉**，标注无对应图像区域。

这一机制的价值在于：**检测与归因的证据来自同一个实验**，因此"区域高亮"不是装饰性功能，而是判定过程的直接产物——高亮出的就是那块使答案翻转的图像，可被使用者立即核验。

三种测试按成本从低到高组成**级联**，早期剪枝，把昂贵的归因测试限制在真正存疑的少数陈述上。

## 配置 API Key

复制 `.env.example` 为 `.env`，填入自己的密钥：

```
VLM_API_KEY=你的密钥
VLM_BASE_URL=https://api.deepseek.com
```

代码会自动读取项目根目录的 `.env`，**不需要每次开窗口都重设环境变量**。

>
> 关于模型选择：本项目验证时使用的是 `deepseek-v4-flash-vision-exp`。**该模型名带 `exp`，属于实验版本，可能随时变更或下线**——这也是本项目必须记录模型版本、并计划接入第二个模型做交叉验证的原因。

## 快速开始

### 1. 先跑离线自检（不联网、不花钱）

```powershell
python code\selftest.py
```

53 项断言覆盖一致性度量、图像遮蔽、指标计算与 yes/no 解析边界。**改完代码先跑它**，能在花掉 API 额度之前发现大部分问题。

### 2. 单张图跑通三种测试

```powershell
python code\halulens.py --task probe_demo ^
  --image test.jpg ^
  --question "Is there a cat in the image?" ^
  --model deepseek-v4-flash-vision-exp
```

预期输出（`test.jpg` 是一张只有几何图形的合成图，问"有没有猫"正确答案是否）：

```
=== 测试输出 ===
  改写一致性： {"score": 1.0, "n_variants": 3, "distribution": {"yes": 0, "no": 3}, "unparseable": 0}
  扰动一致性： {"score": 1.0, "n_variants": 3, "distribution": {"yes": 0, "no": 3}, "unparseable": 0}
  遮蔽归因　： {"baseline": false, "influential_cells": [], "cells_tested": 9, "grid": 3, "has_visual_grounding": false}
```

`has_visual_grounding: false` 在这里是**正确答案**——图中没有猫，所以不存在任何区域被遮蔽后能改变答案。

### 3. 跑批量评测基线

准备一个 jsonl，每行一条：

```json
{"image": "images/01.jpg", "question": "Is there a dog?", "label": 1}
{"image": "images/01.jpg", "question": "Is there an elephant?", "label": 0}
```

`label` 的含义：**1 = 该物体存在（回答 yes 才算对），0 = 不存在（回答 no 才算对）**。

```powershell
python code\halulens.py --task pope_b0 --data mini.jsonl --limit 30 --model deepseek-v4-flash-vision-exp
```

输出 Accuracy / Precision / Recall / F1 / MCC 以及漏检率、误报率。

### 4. 回看模型每次到底说了什么

```powershell
python code\showlog.py              # 最新一次运行
python code\showlog.py --only-null  # 只看解析失败的调用
```

**结果反常时不要靠猜，先跑这个看原话。**

## 关于 `runs/` 目录

每次运行都会在 `runs/` 下写一个 jsonl，包含：

- **运行元信息**：运行时间、请求的模型名、**服务端返回的实际版本**、prompt 版本、生成参数、测试参数
- **成本统计**：实际调用次数、缓存命中率、token 消耗
- **逐次调用明细**：每次的问题、模型的**原始输出**、解析后的判定结果

**为什么这些要进版本管理**：模型服务商可能静默更新模型，没有版本记录的实验结果几个月后无法复现。而原始输出是排查"解析失败"这类异常的唯一依据——否则它只是一个无法诊断的数字。

---

## 复现实验时请注意

1. **记录模型版本**：`runs/` 中已自动记录服务端返回的实际版本号。跨时间比较结果前，先确认版本一致。
2. **对比实验必须同模型同参数**：所有对比方案使用同一个模型、同一版本、`temperature=0`、同一 prompt 模板，否则对比无意义。
3. **区分两种采样设置**：一致性测试内部**允许** `temperature>0`（这是方法的一部分），但用于对比的"主回答"必须固定为 `temperature=0`。
4. **缓存会复用历史结果**：缓存键包含模型名、prompt 版本、图像内容哈希、问题文本与采样参数。任一变化都会产生新条目——**这也意味着修改 prompt 后需要重新产生调用**。

## 已知限制

以下限制均为已知且已在文档中披露，不是待修的 bug：

1. **判定阈值未标定**：0.85 / 0.75 是占位值，需要用真实数据画标定曲线确定。
2. **扰动与问题语义可能冲突**：见上文测试 B 的说明。
3. **"答案恒定"情形的边界**：当任何遮蔽都无法改变答案时，本方法无法区分"该陈述无视觉依据"与"图像本身信息不足"。这是方法的真实边界。
4. **yes/no 解析存在已知盲区**：例如 "I do not see a cat." 这类不含独立 "no" 的否定表达会被判为解析失败。已通过强制格式约束大幅缓解，但未完全消除。
5. **依赖实验性模型**：验证所用模型名带 `exp`，可能变更。
6. **批量评测路径尚未实际运行**：见"项目当前状态"表。

## 关于 AI 协同开发

本项目在开发过程中使用 AI 编程助手协同完成，这符合赛事对 AI 应用创新的鼓励方向。所有 AI 对话记录均通过 `tools/export-ai-log.mjs` 导出留档，**未经人工删改**。

```powershell
node tools\export-ai-log.mjs --list      # 列出全部会话
node tools\export-ai-log.mjs --inspect   # 查看会话记录结构
node tools\export-ai-log.mjs             # 导出为 Markdown（默认不含 AI 思考过程）
node tools\export-ai-log.mjs --full      # 额外保留 AI 的思考过程
```

> 实现说明：DSH 的会话文件是**多帧 zstd 流**（每次写入追加一帧）。Node 的 `zstdDecompressSync` 和 `createZstdDecompress` **都只解第一帧就停止**——实测一个 2 MB 的文件含 4400 帧，直接用现成 API 只能拿到开头 171 个字符。因此本工具自行按帧魔数切帧、逐段解压。
